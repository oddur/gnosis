When a PR has merge conflicts with its base branch, Gnosis can resolve them with you. It merges the base branch into the PR's branch with a merge commit. It does not merge the PR.

## Two safety rules

- **Gnosis never merges a conflict that it cannot prove.** A proposal that the checks do not prove waits for your choice. The draft keeps the conflict markers until you choose.
- **Nothing is pushed without your confirmation.** Only the **Review and push…** confirmation pushes, and only when you select **Push merge commit**.

## When to use this

Use it when the PR has conflicts and you can push to its branch. Gnosis cannot resolve binary files, renames, deletions, folder or file-mode conflicts, or more than 100 conflicted files. It marks them **Needs a local merge tool**, and then cannot push the update. Finish the merge on your computer with the commands that Gnosis gives you.

## Open the conflicts

Select **Resolve conflicts…** in the PR header, in the PR's menu, or in the stack overview.

## Merged, Check and Decide

Gnosis puts each conflict in one of three groups:

- **Merged**: the checks prove the proposal, and it is in the draft. **Decide myself** removes it.
- **Check**: the checks do not prove the proposal. The draft keeps the markers until you choose.
- **Decide**: there is no proposal. You must choose.

A model's proposal is always **Check**, never Merged.

## Resolve a conflict

For each conflict, choose one option:

- **Keep PR change** (<Kbd keys="1" />), **Keep main's change** (<Kbd keys="2" />) or **Keep both** (<Kbd keys="3" />). The button names your base branch.
- **Use the proposal** (<Kbd keys="a" />). Gnosis then goes to the next conflict that needs you.
- **Edit** to write the result yourself, or **Edit whole file** to change lines outside the conflicts too.

Press <Kbd keys="u" /> to undo. Press <Kbd keys="j" /> and <Kbd keys="k" /> to move between conflicts, and <Kbd keys="n" /> and <Kbd keys="p" /> to move between files. Press <Kbd keys="v" /> to compare the result with the PR, the base branch, or both.

A band and a thin rail at the left mark lines that neither side wrote. Read them carefully.

### Ask a model

Nothing goes to a model until you ask. Select **Ask Claude…** (the button names your model). Its menu has two asks:

- **Ask Claude about 2 conflicts** asks about each open conflict on its own. Gnosis sends the conflict, the code around it, the file path, the branch names and the PR title.
- **Ask Claude about** *file* asks about the whole file. Gnosis sends the whole file in all its versions (the common ancestor, the PR's, the base branch's and your draft), the PR's address, and your instructions.

Both asks refuse files and text that look like secrets.

### Mark the file reviewed

When no conflict is left, select **Mark reviewed**, or press <Kbd keys="m" />. Gnosis saves your draft automatically.

By default, you also mark files that have only Merged conflicts. To let Gnosis mark those files for you, clear **Review Merged-only files myself**. Press <Kbd keys="g" /> to turn it on again.

## Review and push

1. When every file is reviewed, press <Kbd keys="⌘ ↵" /> or select **Review and push…**. This opens the confirmation. It does not push.
2. Read the update. It has three groups: **You decided**, **Merged for you** and **Arriving from main**.
3. Write a commit message.
4. Select **Push merge commit**, or press <Kbd keys="⌘ ↵" /> while the button has focus. Enter alone never pushes.

If someone pushed to the PR's branch after you started, the push is refused and nothing changes. Select **Load latest changes**; your resolutions that still apply stay.

If new base commits cause new conflicts, Gnosis pushes nothing and shows them to you.

## Settings

- **Type check**: in <Setting name="Local clone" section="Repositories" />, turn on **Type-check conflict resolutions**. Gnosis then runs the TypeScript compiler from your clone. A new error moves the Merged conflicts to Check. The clone needs TypeScript in its node_modules and a tsconfig.json at its root. The check never runs for PRs from forks.
- **Undo an update** <Prerelease />: in <Setting name="Undo conflict updates" section="Repositories" />, turn on **Allow undoing a conflict update with a force push**. It is off by default. **Undo this update** then resets the branch to its earlier commit, unless someone pushed after you.

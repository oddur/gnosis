A PR in Gnosis has tabs: **Summary**, **Changes**, **Commits**, **Checks**, **Explanation** and **Local notes**. While you resolve merge conflicts, a **Conflicts** tab also shows. This page tells you how to read a PR on each tab.

## When to use each tab

- Use **Summary** first. It tells you what the PR is, who is in it, and if it can merge.
- Use **Changes** to read and review the code.
- Use **Commits** to read the PR one commit at a time.
- Use **Checks** when a check fails.
- Use **Explanation** for a guided walkthrough. See [Explanations](/docs/explanations/).
- Use **Local notes** to keep private notes about the PR.

## Summary

A PR opens on its Summary tab. Summary shows:

- the description;
- the timeline of comments and reviews;
- the people and labels, which you can change;
- the readiness: whether the PR can merge, and what blocks it;
- the time that Gnosis last checked GitHub, for example "Checked 2m ago".

## Changes

Changes shows the diff of the PR. A file tree is on the left.

### Read the diff

- Press <Kbd keys="s" /> for the split diff, and <Kbd keys="u" /> for the unified diff. Press <Kbd keys="d" /> to switch between the two.
- Press <Kbd keys="w" /> to show or hide quiet changes: whitespace, formatting, comments and imports. See [Code intelligence](/docs/code-intelligence/).
- Open **Diff appearance** to set the layout, line numbers, line wrap and change highlights. These settings apply to all diffs.
- Expand the gaps between hunks to see more lines around a change.
- For a Markdown file, choose **Preview** to read the rendered page, or **Source** to read the text.
- For an image, Gnosis compares the old image with the new image.

### Find the changed functions and classes

<Prerelease /> A TypeScript, JavaScript, Python, Go, Rust, Java or C# file in the file tree has a chevron. Select the chevron to see the functions, classes and methods that the file's changes touch. The file you read opens by itself.

- Select a symbol to go to it in the diff. As you scroll the diff, the file tree highlights the symbol that you read.
- Changes outside every function and class show first, as **Imports** or **Top level**.
- A class that is not changed, but has a changed method, shows in gray so you can open it.
- Each symbol shows its added and removed lines. A symbol whose changes are only formatting or comments shows a short word, such as **Format**, instead.
- To mark a symbol as viewed, select it and press <Kbd keys="v" />, or right-click it. The symbol then shows a gray check (**✓**) in place of its counts. This updates the outline above the diff too.
- The search box above the file tree also finds symbol names.

To turn this on or off, clear or select **Symbols** above the file tree, next to **Unviewed only**. This is the same setting as <Setting name="Show changed symbols in the file tree" section="Review" />.

### Review symbol by symbol

<Prerelease /> When the file tree shows changed symbols, it also shows your progress through them.

- After you mark a symbol of a file as viewed, the file shows how many of its changed symbols are viewed, such as **2/5**, instead of its added and removed lines. Symbols with only formatting or comment changes do not count. The **Imports** or **Top level** row counts as one more symbol: mark it as viewed with <Kbd keys="v" />, right-click, or its tick in the outline above the diff.
- When you mark the last changed symbol of a file as viewed, Gnosis marks the file as viewed. The file stays open while you read it, and it collapses when you go to another file or scroll past it. If you clear the mark of one symbol, the file is not viewed any more, and the other symbols stay marked.
- If you clear the **Viewed** checkbox of a file, its symbols keep their marks. The file then shows a gray check, such as **✓ 5/5**, until you mark it again.
- A class or namespace whose changes are in its methods is not a symbol to mark: it shows a gray check when everything in it is viewed. If the class has changes of its own, such as a changed field, they show as a **Body** row first under it, which you mark like a symbol.
- A folder shows the total for its files, for the files whose symbols Gnosis has read.
- Press <Kbd keys="n" /> to go to the next symbol that is not viewed. Press <Kbd keys="⇧ N" /> to go to the previous one. Gnosis starts at the symbol that you read, or at the symbol that you selected in the file tree. It skips viewed files and opens the file of the symbol in the file tree. If it must read the symbols of the next file first, it shows **Loading symbols…**. At the last symbol, it tells you that there are no more symbols after it.
- To mark symbols as viewed while you scroll, turn on <Setting name="Mark a symbol viewed after you scroll through it" section="Review" />. A symbol is marked after all of its changed lines were on the screen and you stayed on it for a moment. Symbols that you scroll past quickly are not marked.

### Review with V

<Prerelease /> To review a PR one change at a time, turn on **Unviewed only** and **Symbols** above the file tree.

1. Select the first symbol in the file tree, or press <Kbd keys="n" />.
2. Read it, then press <Kbd keys="v" />. Gnosis marks it as viewed and goes to the next symbol that is not viewed. A file without symbols, such as a JSON file or an image, is one step.
3. Press <Kbd keys="v" /> again until nothing is left. The toolbar shows how many items are left. When you mark the last symbol of a file, Gnosis marks the file as viewed and goes on to the next file.

If you press <Kbd keys="v" /> by mistake, press <Kbd keys="⇧ V" /> to undo it and go back. When everything is viewed, Gnosis shows **Everything viewed** with a button to review the PR.

### After the author pushes

<Prerelease /> When the file tree shows symbols, a new push keeps your marks on the code that did not change. Gnosis compares each symbol you marked as viewed with the new version of the PR. Changes to spaces and blank lines do not count.

- A symbol that is the same stays marked as viewed. If every symbol of a file is the same, the file stays viewed.
- A symbol that changed shows **↻** in the file tree and in the outline above the diff, and is not viewed any more. The toolbar shows how many items changed, such as **2 updated**. <Kbd keys="n" /> and <Kbd keys="v" /> go to them like to any other item that is not viewed.
- A file without symbols stays viewed if its changes are the same.
- Marks that you made before this version of Gnosis do not carry over.

### Mark files as viewed

Select the **Viewed** checkbox of a file when you finish it, or select the file in the file tree and press <Kbd keys="v" />. This works for every file, also files without symbols, such as JSON or Markdown files. To mark a whole folder, right-click it in the file tree and select **Mark folder as viewed**. This marks only the files that match your filters. To start again, select **Reset viewed** under the file tree. This clears **Viewed** for every file and symbol in these changes, also the files that your filters hide. Select **Undo** in the message that shows to get them back.

Viewed marks stay on your computer. They do not change the Viewed boxes on GitHub.

### Ask about a file

Press <Kbd keys="c" /> to open chat beside the file. See [Chat](/docs/chat/).

## Commits

Commits lists the commits of the PR. Select a commit to see only its diff.

## Checks

Checks shows the CI results for the PR's last commit.

1. Choose **List** to see each check, or **Graph** to see the workflow as a graph.
2. In the list, filter by **All checks**, **Needs attention** or **Running**.
3. Select a check to see its steps and its annotations. For a GitHub Actions job, select **Load log** to read the log. Gnosis shows the first 2 MB; open GitHub for the complete log.
4. To run failed jobs again, select **Re-run failed jobs**. You must have write access to the repository.

## Local notes

Local notes are private notes about lines of code in the PR. Gnosis saves them on your computer and never posts them to GitHub. Use them to collect work for a coding agent.

1. In Changes, start a comment on a line. See [Comments & reviews](/docs/comments-and-reviews/).
2. Under **Save as**, choose **Local note**, then select **Add local note**.
3. Open the Local notes tab. Select **Preview** to see what your agent receives.
4. Select **Copy for agent**. Gnosis copies your notes with the code, the file locations and the version that you reviewed. Paste the text into your coding agent.

## Anti-Patterns Verdict — **PASS**

This is the headline result. If you showed the current build to someone and said "AI made this," they would not believe you. Specific verifications:

- **No cyan-on-dark anywhere.** `grep` for `cyan|teal|sky-|text-blue|border-blue|bg-blue|indigo|purple-|orange-|text-yellow|bg-yellow|border-yellow|text-green-\d|text-red-\d` across all `.tsx`/`.ts` returned **zero matches** other than a comment string in `LoadingScreen.tsx:85` describing what was removed.
- **No glow / box-shadow accents.** `--accent-glow` is gone, `.hero-glow` is gone, `box-shadow: 0 0 20px ...` is gone. The only `shadow-lg` that survives is in `components/ui/sheet.tsx`, which is the unused shadcn Sheet primitive (the project uses a custom `SlideChatSheet`, not the shadcn sheet). The `components/ui/dialog.tsx` shadcn primitive still has `shadow-lg` and `bg-black/50 backdrop-blur-sm` — those are vendored shadcn defaults that survive in dialog rendering. Acceptable for modal elevation but worth a P3 review.
- **No pulse-ring or concentric-ring loaders.** `loading-ring*` classes deleted, `@keyframes pulse-ring` deleted, `Brain` icon removed from LoadingScreen. The replacement is a 1px hairline progress bar.
- **No glassmorphism translucent fills.** The two `backdrop-blur-[2px]` usages are on the `ShortcutOverlay` and `CommandPalette` backdrops — 2px is barely perceptible, used for slight separation between the overlay and the page underneath, not as decoration. Editorial-acceptable.
- **No cards-in-cards.** `grep` for `<Card>|<CardContent|<CardHeader|<CardTitle|<CardDescription` across all `.tsx` returned **zero matches**. Every `Card` wrapper that existed in the original codebase has been removed.
- **No icon+UPPERCASE-TRACKING-WIDER section labels.** Only ONE remaining `uppercase tracking-wide` use, in `CommandPalette.tsx:152` for group headings. The brief explicitly allows uppercase for "at most ONE element" — the command palette group heading is that role.
- **Inter is not loaded.** `index.html` loads Plus Jakarta Sans + Fraunces variable + JetBrains Mono + Fira Code. `'Inter'` does not appear in any source file.
- **Serif IS used on slide titles.** `.slide-title` class uses `var(--font-serif)` (Fraunces) at `clamp(1.75rem, 0.9rem + 2.4vw, 2.625rem)` weight 420 with `font-variation-settings: 'opsz' 96`. Verified in `SlideView.tsx:126` and `ReviewPage.tsx` empty state.

## Detailed Findings by Severity

### [P1] Diff line numbers invisible in light mode

- **Location:** `components/InteractiveDiffHunk.tsx:117`, `components/SplitDiffHunk.tsx:65`
- **Category:** Accessibility / Theming
- **Impact:** Line numbers in interactive diffs are styled with `color: 'rgba(255,255,255,0.3)'` inline. This works against the dark `--background`, but in light mode the line numbers become near-invisible (white at 30% alpha on warm paper ≈ unreadable). Reviewers in light mode lose the line-number context entirely — they have to count rows.
- **WCAG/Standard:** WCAG 1.4.3 Contrast (Minimum) — fails AA in light mode.
- **Recommendation:** Replace the inline `color: 'rgba(255,255,255,0.3)'` with `var(--muted-foreground)` (already contrast-tested in both modes) or move the line-number styling into `globals.css` as a `.diff-line-number` class with proper light/dark handling.
- **Suggested command:** `/polish`

### [P1] Diff line numbers in InteractiveDiffHunk also pre-existing user uncommitted change

- **Location:** `components/InteractiveDiffHunk.tsx:91`
- **Category:** Code quality (lint baseline)
- **Impact:** Pre-existing `no-unnecessary-condition` lint error from the user's uncommitted in-progress changes that were on disk at session start. Doesn't affect runtime, but pollutes the lint baseline.
- **Recommendation:** Surface to the user — they may want to commit or revert their in-progress work before the rest of the redesign lands.
- **Suggested command:** none — flag for the user.

### [P2] Comment-add icon in diff is hardcoded cool blue

- **Location:** `components/InteractiveDiffHunk.tsx:142`, `components/SplitDiffHunk.tsx:54`
- **Category:** Theming / Anti-Pattern
- **Impact:** The `MessageSquarePlus` icon that appears on hover next to a diff line uses `style={{ color: '#58a6ff' }}` — a cool blue. The brief explicitly says comment affordances should use the brand amber as punctuation (which is exactly what `/colorize` did for the file-comment counter pill at the top of each diff group). The hover icon was missed because it's an inline `style` attribute, not a Tailwind class, so it didn't show up in the original colorize sweep.
- **Recommendation:** Replace `#58a6ff` with `oklch(0.65 0.13 65)` (the brand amber). Same fix in both files.
- **Suggested command:** `/polish`

### [P2] Dialog backdrop is a heavy `bg-black/50` with `backdrop-blur-sm`

- **Location:** `components/ui/dialog.tsx:29`
- **Category:** Anti-Pattern / Theming
- **Impact:** Vendored shadcn primitive uses a 50% black backdrop with a small blur. Against the warm-paper light mode, this drops the underlying page to a muddy gray; against warm-charcoal dark mode it goes near-black. Both feel heavier than the rest of the app's editorial register, where `ShortcutOverlay` and `CommandPalette` use a much lighter `bg-background/85 backdrop-blur-[2px]` that respects whichever mode the user is in.
- **Recommendation:** Update `components/ui/dialog.tsx` to use `bg-background/85 backdrop-blur-[2px]` like the custom overlays.
- **Suggested command:** `/polish`

### [P2] Dialog content card uses `shadow-lg` and `rounded-lg`

- **Location:** `components/ui/dialog.tsx:51`
- **Category:** Anti-Pattern
- **Impact:** Same vendored shadcn primitive — dialog content has `rounded-lg border p-6 shadow-lg`. The `shadow-lg` adds a heavy drop shadow that conflicts with the editorial register (which uses hairlines, not shadows). The radius is fine; the shadow is the issue.
- **Recommendation:** Drop `shadow-lg` from the dialog content class. The hairline border + the backdrop are enough to elevate the dialog above the page.
- **Suggested command:** `/polish`

### [P2] FirstRunWelcome "Get started" button is unstyled `<button>` rather than `<Button>`

- **Location:** `components/FirstRunWelcome.tsx`
- **Category:** Consistency
- **Impact:** The primary "Get started →" CTA on the welcome screen uses a manually-styled `<button>` with `bg-primary text-primary-foreground` rather than the project's `<Button>` component. Functionally identical, but it bypasses the Button component's focus styling and hover transitions. Inconsistent with how the rest of the app builds primary CTAs.
- **Recommendation:** Replace with `<Button>` from `@/components/ui/button` so it picks up the same focus ring and hover behavior as every other primary action.
- **Suggested command:** `/polish`

### [P3] Tooltip primitive still in use for history delete buttons

- **Location:** `src/pages/HomePage.tsx` (Tooltip on "Remove merged & closed PRs" and "Delete all history")
- **Category:** Theming
- **Impact:** Two shadcn `<Tooltip>`s remain in the history header, used to label the two icon-only delete buttons. Functionally fine — provides accessible labels — but they render as small floating chrome that hasn't been swept into the editorial vocabulary. They look like "shadcn defaults."
- **Recommendation:** Either restyle the Tooltip primitive to match the editorial register (quiet hairline-bordered popover) OR replace with native `title` attributes (acceptable since these are decorative-only labels for icons that already work via `aria-label`).
- **Suggested command:** `/polish`

### [P3] Avatar shadcn primitive still in use

- **Location:** `src/pages/HomePage.tsx` account row
- **Category:** Theming
- **Impact:** The `Avatar` / `AvatarImage` / `AvatarFallback` shadcn primitives wrap the GitHub avatar in the account row. They render a small round image — fine functionally, but the AvatarFallback uses default shadcn token colors that may not match the new warm palette perfectly. Worth a glance.
- **Recommendation:** Quick visual check on whether the fallback bg looks right. Likely fine.
- **Suggested command:** `/polish`

### [P3] `.kbd` background invisible in dark mode

- **Location:** `src/globals.css` `.kbd` rule
- **Impact:** The keyboard chip uses `background: oklch(0.55 0.012 65 / 6%)` — only 6% alpha against the warm-charcoal dark background, which is essentially invisible. The hairline border still defines the chip shape, so functionally the chip reads, but the fill doesn't add anything. Could be lifted to ~10% in dark mode for slightly better legibility.
- **Suggested command:** `/polish`

## Patterns & Systemic Issues

1. **Inline style attributes bypass the token system.** The two P1/P2 hardcoded colors I found (`#58a6ff`, `rgba(255,255,255,0.3)`) are both inline `style={{}}` props on diff components. The original `/colorize` sweep grepped for Tailwind utility classes and found everything in that vocabulary, but inline style colors slipped through. Worth a follow-up grep pattern in future audits: `style=.*color:` and `style=.*background:`.

2. **Vendored shadcn primitives are an unswept surface.** `components/ui/dialog.tsx`, `components/ui/sheet.tsx`, `components/ui/tooltip.tsx`, `components/ui/badge.tsx`, etc. all carry the original shadcn defaults from `npx shadcn add`. Most are unused (like `sheet.tsx`) or only minimally used (`Tooltip`). The dialog primitive is the most-used and has the most surface area to fix. Long-term option: either fork these to match the editorial register, or delete the unused ones.

3. **The `prefers-reduced-motion` rule covers everything by virtue of using the universal selector.** This is a feature, not a bug — every transition and animation in the app, current and future, will be honored without additional effort. Worth keeping.

## Positive Findings

- **Zero `<Card>` usages anywhere in the codebase.** Every shadcn Card wrapper has been removed.
- **Single source of truth for keyboard shortcuts.** `ShortcutOverlay` documents what exists and what's coming; `useKeyboardShortcuts` enforces it; `CommandPalette` provides a discoverable way to find commands without memorizing keys. The three layers are tied together cleanly.
- **Light + dark mode parity.** Every status pill, banner, and chip now has both light-mode (text at L≈0.42) and dark-mode (text at L≈0.72) variants. Both modes hit WCAG AA contrast for text and 3:1 for borders.
- **Focus ring is unified across every focusable element.** Buttons, links, summaries, tabindexed elements — all use the same warm-amber `var(--ring)` outline. Inputs use a border-color shift instead so the editorial bottom-bordered input style isn't doubled.
- **Skip-to-content link is in place.** Keyboard users no longer have to tab through the persistent header before reaching slide content.
- **Color is used as punctuation, not category shorthand.** The status line in OverviewSlide proves this most clearly: only segments that signal a *problem* get color (warn = amber, error = coral); everything else is just text. Reads like a printed report.
- **Bundle size is healthy.** The built renderer is ~582KB. Shiki, Mermaid, and react-markdown are all still loaded but no new heavyweight dependencies were added during the redesign.

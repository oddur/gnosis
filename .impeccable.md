# Gnosis design context

This direction replaces the previous editorial and newspaper guidelines.
It records the agreed direction, not a claim that the current UI implements it.
Product facts live in [PRODUCT.md](PRODUCT.md).
The implementation plan lives in [docs/review-workbench-plan.md](docs/review-workbench-plan.md).

## Users and purpose

Engineers review a high volume of PRs while maintaining their understanding of the codebase.
They use laptop windows and need fast triage with a clear path into detailed review.
Standalone PRs and stacks receive the same complete experience.

## Visual direction

Use a compact, restrained desktop-tool style.
Use sans-serif typography for titles, prose, navigation, and controls.
Reserve monospace for code and identifiers.
Use modest heading sizes, smaller margins, and subtle panel backgrounds.
Keep prose readable. Recover space through composition rather than uniformly smaller text.
Use color for selection, status, code changes, and meaningful diagram relationships.
Give light and dark themes equal attention.

Remove newspaper treatments: mastheads, decorative rules, editorial serif titles, article columns, and newspaper terminology.
Keep the interface calm, clear, and direct.

## Workspace

The home screen is an attention queue with repository filters.
Stacks appear as expandable groups with a combined purpose and member status.
A compact briefing introduces each PR or stack.

Explanation and code occupy two main panes during detailed review.
Navigation can collapse.
Chat and interactive diagrams temporarily occupy a pane without losing the previous view.
PR attribution remains visible throughout a stack review.

## Accessibility

All actions support keyboard navigation and visible focus.
Meaningful text and controls meet WCAG AA contrast requirements.
Status never depends on color alone.
Motion explains state changes and respects reduced-motion preferences.
